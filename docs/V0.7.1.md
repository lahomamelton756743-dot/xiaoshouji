# little-phone v0.7.1 实施记录

基线：stable v0.6.3。

## 回归顺序

1. v0.6.3 原后端测试通过后才开始改动。
2. 导航改为 日记 / 留痕 / 首页 / 信箱 / 状态，默认首页。
3. 首页重排，不改稳定 bootstrap/cache 数据读取层。
4. 信箱、留痕、状态分别调整并持续跑 Worker 回归。
5. 最后处理身份字体、背景、玻璃与动画。

## v0.7.1 关键实现

- Android `versionCode 70310`，避免安装降级错误。
- `LittlePhoneHTTP` 统一记录请求 endpoint、真实 URL、HTTP code、response 前缀和 JSON parse error。
- 首页完整月历直接展开；日期标记继续保存 `mark_style` 与稳定 `marked_by=user|daddy`。
- 日常册继续 `date ASC → created_at ASC`；更新原 ID。
- 普通信与未来信分开；未来信未解锁时后端不返回 `content`。
- 记忆继续使用 `lp_memories`，MCP 增加 `list/create/update/confirm/correct/delete_little_phone_memory` 明确工具名；旧记忆工具保留兼容。
- `open_little_phone_app` / `open_app` 只进入 Cloudflare command queue。
- 历史 Render server、Blueprint、legacy Cloudflare compatibility worker 与历史部署文档从 v0.7.1 交付包移除；本地 MCP 明确 deprecated，无静默 fallback。

## 真机必须再确认

本地测试无法替代用户现有线上 D1 和 Android 真机，因此安装后必须确认远端历史数据全部回来，并观察 `LittlePhoneHTTP`。如果纸条、信箱、来电、待办、日记、日常册等同时为空，应停止 UI 排查，先检查网络日志与 Worker 配置。

## 当前构建环境限制

本次沙箱缺少 Android SDK platform 34 / build-tools 34.0.0，且无法联网补装，因此不能在这里诚实标记 APK 编译/签名通过。源码、Worker 回归、前端运行时 harness 与 ZIP 完整性仍会完整验证；APK 需要在具备 Android SDK 34 的构建机上执行 `android/build.sh`。
