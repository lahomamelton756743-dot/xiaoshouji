# 归栖备份：GitHub 私有仓库五份轮换（实施方案）

状态：设计与实施清单；尚未启用自动备份，不能视为已完成备份。

## 已确定的用户要求
- 在应用内显示中文名称「归栖备份」；GitHub 仓库建议命名 `guiqi-backup`，**Private**。
- 每日自动备份一次，另有「立即备份」。
- 仅保留最近 **5 份成功备份**，第 6 份经验证后才淘汰最旧一份。
- 支持列出五个恢复点并选择恢复；不得未经确认覆盖现有数据。
- 旧备份不能在 Git 提交历史中被误称为已彻底删除。

## 现状与阻断
- Android 现有「保存回忆快照到手机」只导出已同步或缓存的文字记录，不是完整服务器备份，也没有恢复流程。
- 后端以 Cloudflare D1 为主；必须先确认全部持久化表、R2 媒体对象与其他存储的覆盖范围。
- 当前 GitHub 连接没有创建仓库权限接口，需用户创建 Private 仓库并授予 GitHub App 对该仓库的访问权限。
- Cloudflare Worker 需由用户配置仓库专用、最小权限凭证及独立加密密钥为 Secrets；绝不在 APK、仓库代码、日志或聊天中放明文凭证。

## 安全实施顺序
1. 用户创建 Private `guiqi-backup` 仓库，并将 GitHub App 授权到该仓库。
2. 后端枚举 D1 表和媒体存储，定义带 schema_version、created_at、manifest、校验摘要的备份格式。
3. 后端使用 Web Crypto 加密完整备份；密钥只存在服务端 Secret，确认密钥遗失后的恢复策略。
4. GitHub API 上传新备份，读取回验成功后才更新索引、删除超额旧文件；失败时保留原五份。
5. 注意 Git 历史保留旧文件；如要求真实物理容量固定，应改用对象存储或独立重建历史的仓库策略，且需明确数据丢失风险。
6. Cloudflare Cron Trigger 每日运行，记录最近成功时间、失败状态；禁止并发备份相互清理。
7. 实现恢复前预览、二次确认、恢复前保护性备份、事务或可回滚的恢复操作。
8. Android 设置页接入备份状态、立即备份、恢复点列表、恢复操作；旧的本地 JSON 快照保留并明确标识为非完整备份。
9. 在隔离数据库上验证全量备份、恢复、五份轮换、失败重试、权限和敏感信息泄漏。

## 非目标
- 不在没有凭证与仓库授权时宣称已部署。
- 不把本地缓存导出当成完整备份。
- 不在新备份校验成功前删除旧备份。
